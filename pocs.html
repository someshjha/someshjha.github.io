  1. 01 / Durable execution Scaffolded

    Clinical evidence review

    Can AI-assisted screening reduce reviewer effort without weakening recall or traceability?

    A Temporal workflow coordinates literature search, structured model screening, and human verification. A worker can fail mid-search and resume without repeating completed work. Model suggestions and reviewer decisions remain separate so corrections propagate by construction.

  2. 02 / SLA-bound review Planned

    Fraud case investigation

    Can a long-running investigation stay durable across a human review SLA without losing state if a worker restarts?

    A Temporal workflow runs automated fraud checks, retries a flaky device-intelligence call without hand-written retry logic, then waits on an analyst's signal against an SLA timer. Killing and restarting the worker mid-case resumes exactly where it left off — nothing already completed re-runs, nothing in flight is lost.

    • Temporal
    • Python
    • FastAPI
    • PostgreSQL

  3. 03 / Database trust Planned

    Database column masking by role

    Should the same query return a different record shape when the caller's responsibilities change?

    This test moves role-scoped visibility to the database boundary. Support and finance users see different portions of the same customer record without relying on application code to hide sensitive columns.

    • PostgreSQL
    • Column security

  4. 04 / Agent access Planned

    Scoped financial-data tools for agents

    Can an agent receive only the financial-data capabilities its current task is allowed to use?

    An MCP server exposes scoped tools instead of a standing API key. Every call is constrained by the calling context and produces an audit trail that can be reviewed independently of the agent conversation.

  5. 05 / Event correctness Runnable locally

    Orders and payments streaming pipeline

    Can event-time correlation remain correct through duplicates, late arrivals, and checkpoint recovery?

    Kafka decouples ingestion while Flink joins payments to orders in event time, deduplicates by event ID, and recovers without double-counting. PostgreSQL serves current state and minute-level revenue metrics for live verification.
